# Catalogs

## `audio_clips_catalog.csv`

Generated by `scripts/build_catalog.py` from the read-only NPS acoustic highlights volume. Each row represents one audio file (`.wav`, `.mp3`, or `.aiff`) discovered via filesystem walk (~4,210 rows).

Core columns include `filepath` (relative to the highlights root), `category_folder` (top-level taxonomy folder or `root`), filename-derived fields (`parsed_park_code`, `parsed_site_code`, `parsed_date`, `parsed_time`, `free_text_description`, `parse_confidence`), and `sensitive_flag` (true for anything under `HUMANS OH HUMANS/`). Xeno-Canto metadata from the FINAL2020 upload spreadsheet (with draft fallbacks) is joined on filename stem, case-insensitively and extension-agnostically, into `xc_*` columns when matched.

## `highlights_catalog.json`

Generated by `scripts/build_highlights_catalog.py` from the curated 126-clip MVP set in `highlights/audio/`. This is the production catalog consumed by the static site build.

Known limitations: parsed dates and times in `audio_clips_catalog.csv` come from filenames only and are not validated against audio content or embedded file metadata. Many `free_text_description` values still contain processing tags (e.g. AMPLIFY, BANDPASS, TRIM) that could be stripped in a future pass. Non-standard filenames receive `parse_confidence` of `low` or `unparsed` rather than forced guesses. `build_catalog.py` does not read or decode audio bytes, so duration and sample rate for the full catalog are out of scope there (those fields are populated in `highlights_catalog.json` from the actual highlight clips).
